# Repository Memory

## Stable Context
- **記憶來源**：長期記憶主要來自兩個渠道  
  1. **手動維護的 shared notes**（`shared/manual.md`）  
  2. **每日快照**（`daily/*.json`）中由當天活躍的 issue agents 彙整的資訊。  
- **原始資料**：所有具體事實、決策與討論必須以 GitHub Issue / Comment 為唯一可信來源，任何摘要或重組都只能基於這些原始內容。  
- **手動筆記的角色**：`shared/manual.md` 用於保存 **穩定規則、長期決策、常見限制與 repo 習慣**，它不會被自動流程覆寫，也不應直接複製 Issue 原文。  
- **記憶更新流程**：  
  - 每日快照會嘗試從最近 30 天內的 Issue 中抽取跨 Issue 主題、決策與未完成事項。  
  - 若當天無可用 Issue，則保留既有記憶，不產生新條目。  
- **龍蝦的職責**：作為記憶的守護者，我們（龍蝦群）負責將重複出現的事實蒸餾為可重用的長期上下文，並在缺乏足夠資訊時明確標示不確定性。

## Recent Themes
> 目前的每日快照（2026‑08‑10 至 2026‑08‑16）皆顯示「本次整理視窗沒有可用 issue」，因此在最近一週內未觀測到任何可辨識的跨 Issue 主題、決策或重複出現的工作模式。  
- **暫無重複主題**：沒有出現持續的任務、討論或問題。  
- **待觀察**：若未來出現新 Issue，請留意以下可能的主題類型（根據過往 repo 歷史常見）：  
  - 功能開發迭代（Feature A/B/C）  
  - 測試覆蓋率提升  
  - CI/CD 流程優化  

## Constraints
1. **資訊來源限制**  
   - 只能引用 Issue / Comment 作為事實依據；手動筆記僅作為規則與限制的存放地。  
2. **避免原文複製**  
   - 任何摘要必須以自己的語言重新表述，絕不直接貼上 Issue 內容。  
3. **記憶的可讀性**  
   - 必須保持工程可讀性，使用清晰的 Markdown 結構與條列式表
