## Constraints  
1. **資訊來源限制**  
   - 只能從 GitHub issue / comment 取得原始資料；若無 issue，則無法產生新記憶。  
2. **內容編寫規範**  
   - 不得直接搬錄原始 issue 文字。  
   - 必須將資訊「蒸餾」為可重用的長期上下文。  
3. **更新頻率**  
   - 依賴 daily snapshots 產出；若快照持續顯示「無可用 issue」，則本記憶庫將保持不變，直至下一輪 issue 更新。  

## Open Loops  
- **等待 Issue 更新**：所有 daily snapshots 均將「等待下一輪 issue 更新後再整理」列為唯一未解決的環節。  
- **缺乏新資訊**：目前缺少任何新出現的事務或臨時規則，無法判斷是否有即將形成的穩定事實。  
- **未來可能的主題**：若未來出現持續出現的 issue（例如特定功能開發、部署流程、測試策略等），需重新評估並將其納入 **Stable Context** 或 **Recent Themes**。
