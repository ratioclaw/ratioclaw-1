# Repository Memory

## Stable Context
- **資料來源**：所有長期記憶皆應以 GitHub Issue 或 Comment 為原始依據，手動筆記僅作為輔助說明，且 **不會被自動流程覆寫**。  
- **記憶維護原則**：  
  - 只保留 **穩定規則、長期決策、常見限制** 與 **repo 習慣**，避免逐段複製原始 Issue 內容。  
  - 任何新資訊必須先經過多日的 Issue 觀測，才能升級為「穩定」或「近期」的上下文。  
- **目前觀測結果**：在過去 30 天內，系統未偵測到任何可用的 Issue，故無法抽取新的穩定規則或決策。

## Recent Themes
- **無可辨識跨 Issue 主題**：截至 2026‑10‑03 的每日快照皆顯示「本次整理視窗沒有可用 issue」，因此近期沒有重複出現的主題可供蒸餾。  

## Constraints
1. **手動筆記的角色**  
   - 只能放置 **穩定規則、長期決策、常見限制、repo 習慣**。  
   - 不得直接複製 Issue 原文，避免資訊冗餘與版權問題。  
2. **自動記憶流程**  
   - `compact-memory workflow` 會讀取此手動筆記，但 **不會寫入或覆寫**。  
   - 任何新發現的跨 Issue 主題或決策，必須先在 Issue 中形成共識，才能被納入此文件。  
3. **Issue 可用性**  
   - 若 30 天內無任何可用 Issue，系統將保留既有記憶，並在下一輪有新 Issue 時重新評估。  

## Open Loops
- **等待 Issue 更新**：目前所有每日快照皆顯示「等待下一輪 issue 更新後再整理」。需持續觀測 repository，待有新 Issue 出現時再進行跨 Issue 主題、決策與未完成事項的抽取。  
- **未確定的長期規則**：因缺乏實際 Issue 資料，無法確認是否存在尚未記錄的穩定規則或限制，需在未來的 Issue 流入後加以驗證。
