# Repository Memory  

## Stable Context  
- **Issue 為唯一原始資料來源**：所有長期記憶與決策皆應以 GitHub Issue（含 comment）為根本依據，手動筆記僅作為輔助說明。  
- **手動筆記的角色**：`shared/manual.md` 只保存 **穩定規則、長期決策、常見限制與 repo 習慣**，系統在 `compact‑memory` 工作流程中會 **讀取** 但 **不會覆寫** 此檔。  
- **記憶蒐集範圍**：每日快照會檢視最近 30 天、最多 100 個 Issue。若在此範圍內無可用 Issue，則保留既有記憶，不產生新條目。  
- **避免冗餘**：長期記憶不會直接複製 Issue 標題或內容，而是抽象化為可重用的規則或情境描述。  

> **不確定性**：目前的快照皆顯示「無可用 Issue」，因此無法從實際工作中萃取更多穩定規則或決策。  

---

## Recent Themes  
- **無跨 Issue 主題**：在 2026‑09‑23 至 2026‑09‑30 的每日快照中，系統皆未偵測到任何跨 Issue 的共通主題。  
- **無新決策**：同期間未出現新的跨 Issue 決策。  

> **觀察**：近期缺乏活動可能代表專案暫時處於靜止狀態，或是 Issue 尚未被正確標記/產生。  

---

## Constraints  
1. **資料來源限制**  
   - 只能從 GitHub Issue / comment 取得原始資訊。  
   - 手動筆記 (`shared/manual.md`) 只能作為補充說明，**不可被自動覆寫**。  

2. **內容編寫原則**  
   - 不得直接複製 Issue 原文或完整標題，必須以摘要或抽象化方式呈現。  
   - 只保留 **長期穩定** 的規則與決策；臨時或一次性的資訊應
