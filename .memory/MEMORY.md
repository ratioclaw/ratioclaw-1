# Repository Memory

## Stable Context
- **長期規則**  
  - 只以 GitHub Issue / Comment 為原始資料來源，任何手動筆記皆為輔助說明，**不會**直接覆寫原始 Issue。  
  - `compact‑memory` 工作流程會讀取 **shared/manual.md**，但不會改寫它；因此此檔案的內容必須保持 **穩定且可重用**。  
  - 任何跨 Issue 的決策或主題，若未在多日的快照中持續出現，皆不視為穩定規則。  

- **Repo 習慣**  
  - 每日快照只聚焦過去 30 天內的 Issue，且上限 100 件。  
  - 若當日無可用 Issue，系統會保留既有記憶，並在下一輪有更新時重新整理。  
  - 標籤 (`Top Labels`) 只在有 Issue 時列出，否則保持 `none`。  

- **資訊蒸餾原則**  
  - 只保留 **長期、重複出現** 的事實與規則。  
  - 短暫、單日出現且未形成趨勢的資訊，放入 **Recent Themes** 或 **Open Loops**，不寫成永久規則。  

## Recent Themes
- **缺乏 Issue 活動**：自 2026‑09‑13 起至 2026‑09‑19，所有每日快照皆顯示「本次整理視窗沒有可用 issue」，說明近期 repo 內的 Issue 活動極低或暫停。  
- **無跨 Issue 主題**：每日快照均報告「目前沒有可辨識的跨 issue 主題」，表示目前沒有跨多個 Issue 的共通議題。  
- **無新決策**：同樣的，近期未產生任何跨 Issue 的決策。  

> **註**：上述主題僅因缺乏資料而被視為「近期」狀態，未必代表長期趨勢。

## Constraints
1. **資料來源限制**  
   - 只能從 GitHub Issue / Comment 抽取事實；手動筆記僅作為輔助說明。  
2. **不可直接複製原文**  
   - `shared/manual.md` 不應被完整複製到本檔；僅摘錄規則與限制。  
3. **更新頻率**  
   - 每日快照只檢視最近 30 天內的 Issue，若超過上限或無 Issue，系統會保持現有記憶不變。  
4. **語言與風格**  
   - 本文件以繁體中文撰寫，語氣模
