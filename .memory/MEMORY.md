# Repository Memory

## Stable Context
- **長期規則**  
  - 只以 GitHub Issue 與 Comment 為原始資料來源，其他檔案僅作為輔助說明。  
  - `compact-memory` 工作流程會 **讀取** 本手動筆記，但 **不會覆寫** 它。  
  - 任何新增或變更的長期記憶必須由人類手動編輯 `shared/manual.md`，自動流程僅負責蒸餾與呈現。

- **長期決策**  
  - 目前未偵測到跨 Issue 的決策或策略變更。  
  - 若未來出現持續性的決策，應於此節加入摘要說明。

- **常見限制**  
  - 禁止直接複製完整 Issue 文字至長期記憶檔案，僅保留關鍵概念與規則。  
  - 每日快照僅在有可用 Issue 時才會產生新資訊，無 Issue 時保留既有記憶。  

- **Repo 習慣**  
  - 所有 Issue 均以 **30 天** 為回顧窗口，超過此期限的 Issue 仍會被納入統計。  
  - 每日快照會列出 `Top Labels`、`Open Loops`、`Cross‑Issue Themes` 等欄位，供龍蝦們快速定位重點。  

## Recent Themes
- **缺乏可用 Issue**：連續 7 天（2026‑09‑22 至 2026‑09‑29）皆未偵測到可用 Issue，導致每日快照僅回報「保留既有記憶」與「等待下一輪更新」的訊息。  
- **無跨 Issue 主題**：在同一期間內未出現可辨識的跨 Issue 主題或共通議題。  

> **註**：上述主題僅因資料缺乏而顯示為「無」，若未來出現新 Issue，相關主題將自動加入此節。

## Constraints
1. **資料來源限制**  
   - 只能從 GitHub Issue / Comment 抽取資訊；其他來源（如 PR、Wiki）不列入本記憶體。  
2. **內容編寫限制**  
   - 不得完整複製 Issue 原文，必須以摘要或概念化方式呈現。  
3. **更新頻率**  
   - 每日快照只在有新 Issue 時產生變更，否則保持現有記憶不變。  
4. **手動筆記保護**  
   - `shared/manual.md` 為唯一手動維
