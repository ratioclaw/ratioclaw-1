# Repository Memory

## Stable Context
- **長期規則**  
  - 只允許從 GitHub Issue / Comment 中抽取資訊作為原始資料來源。  
  - `shared/manual.md` 為唯一的手動維護長期記憶檔案，**不可**被自動流程覆寫。  
  - 任何自動化流程（如 compact‑memory）只能 **讀取** 此手動筆記，不能寫入或複製完整 Issue 內容。  
  - 產出之長期記憶檔案（如本 `MEMORY.md`）必須是 **精煉、去重** 的敘述，避免逐段搬錄原始日誌。  

- **Repo 習慣**  
  - 每日快照（`daily/*.json`）由活躍的 issue agents 產出，若當天無可用 Issue，快照會保留既有記憶並標示「無可用 issue」。  
  - 跨 Issue 主題與決策僅在有足夠共通資訊時才會被記錄；目前尚未出現此類共通點。  

- **長期決策**  
  - 目前沒有累積的跨 Issue 決策可供記錄。  

## Recent Themes
- **缺乏 Issue 活動**：自 2026‑11‑18 起的每日快照皆顯示「本次整理視窗沒有可用 issue」，說明近期 repo 內缺乏待處理或新建立的 Issue。  
- **等待更新**：所有快照的 **Open Loops** 都指向「等待下一輪 issue 更新後再整理」，顯示目前的主要關注點是等待新 Issue 的出現。  

> **註**：因為每日快照未提供任何具體議題或標籤，無法從近期資料中萃取出其他重複出現的主題。

## Constraints
1. **資料來源限制**  
   - 只能引用 GitHub Issue / Comment 作為事實依據；其他來源（如聊天記錄、外部文件）不列入本記憶體。  
2. **內容編寫原則**  
   - 不得直接複製 Issue 原文或完整段落。  
   - 必須將資訊 **蒸餾** 成可重用、易於檢索的敘述。  
3. **手動筆記保護**  
   - `shared/manual.md` 為手動維護的長期記憶，任何自動化流程不得修改或覆寫此檔。  
4. **資訊不確定性**  
   - 若資訊僅在單一天出現且未形成穩定事實
