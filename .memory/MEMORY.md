# Repository Memory

## Stable Context
- 目前的日誌中未出現任何可辨識的長期規則、決策或持續性的工作流程。  
- 依據 **Shared Memory Manual Notes**，以下為已確定的穩定原則：
  - 所有長期記憶的來源必須是 **GitHub issue / comment**，而非其他非結構化文字。  
  - `compact-memory` 工作流程會 **讀取** 此手動筆記，但 **不會覆寫**。  
  - 任何 **agent** 必須遵守 repo 的共同慣例（具體慣例尚未在日誌中列出）。

> **不確定性**：除上述手動筆記外，缺乏其他可驗證的穩定事實。

## Recent Themes
- 最近 30 天的每日快照皆顯示 **「本次整理視窗沒有可用 issue」**，因此未產生跨 issue 主題或新決策。  
- 觀察到的唯一重複訊息是 **「等待下一輪 issue 更新後再整理」**，顯示目前的工作狀態處於待命或資料缺乏階段。

## Constraints
- **資料來源限制**：只能使用 GitHub issue / comment 作為原始資訊，避免直接複製完整 issue 內容。  
- **編輯限制**：`compact-memory` 流程只能讀取手動筆記，不能自行覆寫或刪除。  
- **標籤與篩選**：每日快照的 `Issue limit` 為 100，且僅檢視過去 30 天的 issue；若超出此範圍，相關資訊將不會被納入本記憶。  
- **缺乏可用 issue**：當前所有快照皆報告「沒有可用 issue」，因此任何自動化的跨 issue 分析或決策都受到此限制。

## Open Loops
- **Issue 更新待機**：所有快照均列出「等待下一輪 issue 更新後再整理」，表示目前缺少可供分析的 issue。  
- **未確定的長期規則**：尚未在手動筆記或日誌中明確記錄的 repo 習慣、工作流程或限制，需要在未來的 issue 中補充。  
- **潛在的跨 issue 主題**：若未來出現可用 issue，需重新評估是否存在跨 issue 的共同主題或決策。
