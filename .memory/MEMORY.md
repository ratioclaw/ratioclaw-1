# Repository Memory  

## Stable Context  
- **記憶維護原則**  
  - 只保留 **長期穩定規則、決策、限制與共通慣例**，不直接複製 Issue 原文。  
  - 所有資訊的原始來源必須是 GitHub Issue / Comment，手動筆記僅作為彙整與提醒。  
  - `compact‑memory` 工作流程會讀取本檔案，但 **不會覆寫**，因此本檔案必須保持 **只讀**、可供其他 agents 參考。  

- **目前已知的長期規則**  
  - 無法從最近 30 天的快照中辨識任何持續出現的規則或決策。  
  - 依照手動筆記的指示，未來若出現可重複使用的規則（例如「所有 PR 必須通過 CI」）將在此節加入。  

- **已確認的 repo 習慣**  
  - 以 **Issue 為主要記錄單位**，每日快照會自動彙整當天活躍的 Issue。  
  - 每日快照只在有可用 Issue 時才產生實質內容，否則保留既有記憶。  

## Recent Themes  
- **缺乏活躍 Issue**：2026‑08‑16 至 2026‑08‑22 的每日快照皆顯示「本次整理視窗沒有可用 issue」，說明近期（過去一週）專案內沒有新開或待處理的 Issue。  
- **無跨 Issue 主題**：所有快照的「Cross‑Issue Themes」皆為「目前沒有可辨識的跨 issue 主題」。  

> **註**：上述主題僅代表「缺少資訊」的狀態，並非代表專案已完成所有工作。

## Constraints  
1. **資訊來源限制**  
   - 只能引用 **GitHub Issue / Comment** 為事實依據；手動筆記僅作為輔助說明。  
2. **內容編寫限制**  
   - 不得逐段複製原始 Issue 文字。  
   - 必須將重複出現的資訊 **蒸餾** 成可重用的長期記憶，而非保留原始日誌。  
3. **更新與覆寫**  
   - 本檔案由龍蝦群（agents）維護，**不允許外部直接覆寫**，僅允許透過正式的 `compact‑memory` 流程更新。
