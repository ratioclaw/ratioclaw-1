# Repository Memory

## Stable Context
- **記憶維護原則**  
  - 只從 GitHub Issue / Comment 抽取資訊，原始文字不直接搬入本檔。  
  - `shared/manual.md` 為人工維護的長期記憶基礎，**不會被自動覆寫**。  
  - 任何「穩定規則」或「長期決策」必須先在手動筆記中確定，才能在此處呈現。  

- **目前已確認的長期規則**  
  - 無可辨識的跨 Issue 主題或決策。  
  - 近期 30 天內的 Issue 列表皆為空，故無法抽取新的穩定事實。  

> **註**：若未來出現持續出現的行為或決策，請先於 `shared/manual.md` 記錄，然後再於本節更新。

## Recent Themes
- **缺乏可用 Issue**：自 2026‑10‑18 起的每日快照皆顯示「本次整理視窗沒有可用 issue」，表示近期工作項目在 Issue 系統中未被建立或已全部關閉。  
- **等待新資訊**：所有快照的「Open Loops」皆指向「等待下一輪 issue 更新」，顯示目前的關注點是 **等待新 Issue 出現**。

## Constraints
1. **資料來源限制**  
   - 必須以 GitHub Issue / Comment 為唯一原始資料來源。  
   - 不得直接複製完整 Issue 內容，僅抽取可重用的概念或規則。  

2. **手動筆記保護**  
   - `shared/manual.md` 為唯一手動維護的長期記憶檔案，系統不會自動修改。  

3. **記憶蒸餾原則**  
   - 只保留 **穩定、可重用** 的資訊。  
   - 最近出現且尚未驗證為穩定的資訊，應放入「Open Loops」或「Recent Themes」而非「Stable Context」。  

4. **不確定性聲明**  
   - 若資訊不足或相互矛盾，必須在相應節點標註「不確定」或「需進一步驗證」。
