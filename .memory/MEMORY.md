# Repository Memory

## Stable Context
- **記憶手冊原則**  
  - 只保留 **穩定規則、長期決策、常見限制** 以及 **repo 共同習慣**，不直接複製 Issue 原文。  
  - GitHub Issue / Comment 為原始資料來源，手動筆記僅作為摘要與指引。  
  - `compact‑memory` 工作流程會讀取此手動筆記，但不會覆寫它。  

- **目前觀測到的長期事實**  
  - 近期 30 天內的所有 daily snapshot 均未偵測到可用 Issue，表示 **目前 repo 中沒有待處理或新建立的 Issue**。  
  - 因缺乏具體 Issue，無法從日誌中抽取額外的穩定規則或決策。  

> **不確定性**：除上述手冊規則外，沒有其他可驗證的長期事實可供記錄。若未來出現新的 Issue，將會補充相應的穩定上下文。

## Recent Themes
- **無跨 Issue 主題**：連續 7 天（2026‑07‑29 至 2026‑08‑04）皆未出現可辨識的跨 Issue 主題或共通標籤。  
- **持續無 Issue**：每日快照皆報告「本次整理視窗沒有可用 issue」，顯示 repo 近期處於靜止狀態。  

## Constraints
1. **資料來源限制**  
   - 只能從 GitHub Issue / Comment 取得原始資訊，手動筆記僅作為輔助。  
2. **內容編寫規範**  
   - 不得直接複製 Issue 原文；必須以 **精煉、可重用** 的方式呈現。  
   - `MEMORY.md` 必須保持 **工程可讀性**，同時以「龍蝦」的口吻提醒主人。  
3. **更新頻率**  
   - 若未偵測到新 Issue，保持現有記憶不變，待下一輪 Issue 更新後再行整理。  

## Open Loops
- **等待 Issue 更新**：所有 daily snapshot 均標示「等待下一輪 issue 更新後再整理」，因此目前沒有具體的未完成事項可列出。  
- **潛在新規則**：若未來出現持續出現的 Issue 主題或決策，需將其歸入 **Stable Context** 或 **Recent Themes**，並在此處追蹤其進度。
