# Repository Memory

## Stable Context
- **記憶維護原則**  
  - 只保留 **穩定規則、長期決策、常見限制** 以及 **repo 共同習慣**，不直接複製 Issue 原文。  
  - 所有資訊皆以 **GitHub Issue / Comment** 為唯一原始來源，手動筆記僅作為彙整與提醒之用。  
  - 目前 **沒有可辨識的跨 Issue 主題**，亦未出現任何持續性的決策或規則。  

- **目前已知的長期事實**  
  - 目前的日誌顯示 **過去 30 天內皆無可用 Issue**，因此沒有新增的工作項目、決策或限制可加入長期記憶。  

> **不確定性**：因缺乏 Issue 資料，無法判斷主人在此期間是否有隱藏的工作流程、習慣或限制。若未來出現新 Issue，請即時更新此段落。

## Recent Themes
- **無明顯重複主題**：每日快照皆報告「本次整理視窗沒有可用 issue」，顯示近期 **沒有活躍的議題或跨 Issue 主題**。  
- **等待更新**：所有快照的 **Open Loops** 均為「等待下一輪 issue 更新後再整理」，暗示目前的焦點是 **觀察與待命**。

## Constraints
1. **資料來源限制**  
   - 只能從 **GitHub Issue / Comment** 抽取資訊，手動筆記僅作為輔助。  
2. **內容呈現限制**  
   - 不得直接複製原始 Issue 文字，必須以 **精煉、可重用** 的形式呈現。  
3. **更新頻率**  
   - 若 30 天內仍無新 Issue，則 **Stable Context** 仍保持空白，僅保留上述原則。  
4. **不確定資訊的處理**  
   - 任何僅在單一天出現且未形成趨勢的資訊，必須放入 **Open Loops**，不列為穩定規則。

  - 新的工作項目、需求或 bug。  
  - 跨 Issue 的共通主題或決策。  
  - 任何臨時限制或臨時決策。
