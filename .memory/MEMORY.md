# Repository Memory

## Stable Context
- **記憶手冊原則**  
  - 只保留 **穩定規則、長期決策、常見限制** 以及 **repo 共同習慣**，不直接複製 Issue 原文。  
  - GitHub Issue / Comment 為原始資料來源，手動筆記僅作為 **compact‑memory** 工作流的參考，不會被覆寫。  
- **目前觀測到的事實**  
  - 在過去 30 天內，所有每日快照皆顯示 **「本次整理視窗沒有可用 issue」**，因此沒有新增或變更的可觀測資訊。  
  - 沒有跨 Issue 的主題、決策或標籤被辨識出來。  

> **不確定性**：因缺乏可用 Issue，無法確認是否存在尚未被捕捉的長期規則或決策。若未來出現新 Issue，需重新評估並補充此段落。

## Recent Themes
- **無可辨識的跨 Issue 主題**：連續七天的快照皆未偵測到任何共通主題或重複出現的議題。  
- **持續的空白狀態**：每日皆回報「等待下一輪 issue 更新後再整理」，顯示目前的工作流正處於待命狀態。

## Constraints
1. **資料來源限制**  
   - 只能從 GitHub Issue / Comment 取得原始資訊，手動筆記僅供參考。  
2. **內容編寫規則**  
   - 不得直接複製 Issue 原文；必須以 **精煉、可重用** 的方式呈現。  
   - 只能在確定為「穩定事實」時寫入 **Stable Context**，暫時性或單次出現的資訊放入 **Recent Themes** 或 **Open Loops**。  
3. **更新頻率**  
   - 每日快照會在 **UTC 20:00** 左右產生，若當天無可用 Issue，則保留既有記憶，不新增內容。  

## Open Loops
- **等待 Issue 更新**：目前所有快照皆顯示「等待下一輪 issue 更新後再整理」，代表尚未有新 Issue 產生或被標記為可處理。  
- **未確定的長期規則**：若未來出現持續出現的 Issue（例如工作流程、代碼風格、部署策略等），需在 **Stable Context** 中加入相應的穩定規則。
