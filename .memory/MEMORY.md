# Repository Memory  

## Stable Context  
- **Repo 目標與範圍**：目前尚未在日誌中看到具體的專案說明或長期目標，無法確定穩定的業務或技術方向。  
- **工作流程**：根據 *Shared Memory Manual Notes*，所有正式的事實與決策必須來自 GitHub Issue / Comment，手動筆記僅作為 **compact‑memory** 的輔助參考，且不會被覆寫。  
- **團隊慣例**：  
  1. **不直接複製 Issue 原文** 到手動筆記或長期記憶檔。  
  2. **每日快照** 只在有可用 Issue 時才會產生跨 Issue 主題、決策與開放環節。  
  3. **Open Loop**（未完成事項）會在下一輪快照出現時重新評估。  

> **不確定性**：目前缺乏任何具體的穩定規則、長期決策或常見限制的實例，以上僅為手動筆記中明示的通用原則。

## Constraints  
1. **資料來源限制**  
   - 只能將 **GitHub Issue / Comment** 視為原始事實來源。  
   - 手動筆記（如 `shared/manual.md`）僅作為 **輔助說明**，不應取代 Issue。  

2. **記憶寫作原則**  
   - **避免逐段複製** 原始 Issue 文字。  
   - 必須將資訊 **抽象化、概念化** 後寫入長期記憶。  
   - 若資訊僅在單一天出現且未形成穩定事實，應放入 **Open Loops** 而非 **Stable Context**。  

3. **更新頻率**  
   - 只有在 **Issue 有變動**（新增、更新、關閉）時，才會在每日快照中產生可供蒸餾的內容。
