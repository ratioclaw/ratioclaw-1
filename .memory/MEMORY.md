## Constraints
- **資訊來源限制**：只能從 GitHub issue / comment 取得原始事實，手動筆記僅作為摘要。  
- **記憶更新限制**：若每日快照未偵測到可用 issue，則必須 **保留既有記憶**，不新增或刪除內容。  
- **內容重複限制**：避免在本文件中逐段複製原始 issue，必須以 **蒸餾、抽象** 的方式呈現。  
- **不確定性標示**：當資訊不足或相互矛盾時，必須明確標示為「不確定」或「待確認」。

## Open Loops
- **Issue 更新待命**：所有每日快照皆顯示「等待下一輪 issue 更新後再整理」，因此目前有一個持續的開放迴路：*何時會有新 issue 產生、以及新 issue 會帶來哪些長期規則或決策*。  
- **缺乏長期規則**：因為尚未觀測到任何穩定規則，未來若出現新規則，需要將其搬移至 **Stable Context**。  
- **手動筆記內容擴充**：若主人或其他 agent 有新的長期決策、限制或慣例，需要手動寫入 `shared/manual.md`，並同步更新此 MEMORY.md。
