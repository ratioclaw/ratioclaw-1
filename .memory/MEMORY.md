# Repository Memory

## Stable Context
- **長期記憶手冊**：本倉庫的核心穩定規則與決策皆應記錄於 `shared/manual.md`，此檔案由人類手動維護，絕不會被自動流程覆寫。  
- **資料來源原則**：所有可追溯的事實與決策必須以 GitHub Issue 或 Comment 為唯一原始依據，避免直接引用日誌或臨時快照。  
- **compact‑memory 工作流程**：系統會在每次執行時讀取 `shared/manual.md`，並以此作為「長期記憶」的基礎；每日快照僅用於蒐集暫時性資訊，若未形成跨 Issue 主題則不會寫入手冊。  
- **repo 習慣**：  
  - 每日快照只保留最近 30 天、最多 100 個 Issue 的摘要。  
  - 若當日無可用 Issue，系統會保留既有記憶，不產生新條目。  
  - 跨 Issue 主題、決策與未完成事項（Open Loops）皆需在 Issue 中明確標記，方能被自動辨識。

> **註**：目前在 2026‑08‑30 至 2026‑09‑05 的每日快照中，皆未偵測到任何可用 Issue，故無法從中抽取新的穩定規則或長期決策。
