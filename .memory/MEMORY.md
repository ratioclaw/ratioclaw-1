# Repository Memory

## Stable Context
- **資料來源**：所有長期記憶皆應以 GitHub Issue 或 Comment 為原始依據，手動筆記僅作為輔助說明，**不會被自動覆寫**。  
- **手動筆記用途**：`shared/manual.md` 用於保存 **穩定規則、長期決策、常見限制與 repo 習慣**，但不應直接複製 Issue 原文。  
- **工作流程**：系統會在 `compact‑memory` 流程中讀取此手動筆記，以提供上下文給各 agent。  

> **不確定性**：目前尚未在 Issue 中觀測到任何具體規則或決策，故上述內容僅為已知的結構性約定，未形成可執行的業務規則。

## Recent Themes
- **無可辨識跨 Issue 主題**：過去 30 天的每日快照（2026‑10‑10 至 2026‑10‑17）皆未檢測到活躍 Issue，亦未產生跨 Issue 的共通主題。  
- **持續無新決策**：每日快照均報告「目前沒有新的跨 Issue 決策」。  

> **觀察**：近期的「無事」狀態本身是一個可觀測的模式，表示目前 repo 內缺乏待處理的工作項目。

## Constraints
1. **原始資料限制**  
   - 只能從 GitHub Issue / Comment 抽取事實與決策。  
   - 手動筆記僅作為補充說明，不能作為唯一依據。  

2. **記憶更新限制**  
   - `compact-memory` 只會 **讀取** `shared/manual.md`，不會 **寫入** 或覆寫。  
   - 每日快照僅在有可用 Issue 時才會產生具體內容，否則保留既有記憶。  

3. **資訊完整性**  
   - 若每日快照未提供資訊，系統必須保留先前已確認的上下文，避免因缺失而產生錯誤假設。  

## Open Loops
- **等待 Issue 更新**：所有每日快照均顯示「等待下一輪 issue 更新後再整理」，因此目前沒有具體的待辦事項。  
- **未確定的長期規則**：因缺乏實際 Issue，尚未形成任何可驗證的穩定規則或決策。  
- **潛在的主題探索**：若未來出現新 Issue，需重新評估是否形成跨 Issue 主題或決策鏈。
