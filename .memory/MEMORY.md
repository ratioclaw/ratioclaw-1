# Repository Memory

## Stable Context
- **記憶維護原則**  
  - 只保留 **穩定規則、長期決策、常見限制** 以及 **repo 共同習慣**，不直接複製 Issue 原文。  
  - 所有原始資訊皆來自 GitHub **issue / comment**，本檔僅作為摘要與萃取。  
  - `compact‑memory` 工作流程會讀取本手動筆記，但不會覆寫它。  

- **目前已確認的長期規則**  
  - 無可辨識的跨 Issue 主題或決策。  
  - 近期 30 天內的每日快照皆顯示「本次整理視窗沒有可用 issue」，因此 **沒有新增的穩定事實** 可加入此段落。  

> **不確定性**：因缺乏可用 Issue，無法確認是否存在隱藏的長期規則或決策。待未來有 Issue 出現時再行補充。

## Recent Themes
- **缺乏活躍 Issue**：連續 7 天（2026‑10‑22 至 2026‑10‑28）皆未偵測到可用 Issue，說明目前專案在此期間 **沒有新需求、錯誤或討論**。  
- **等待更新**：每日快照皆將「Open Loops」標示為「等待下一輪 issue 更新後再整理」，顯示 **資訊流暢度受限於 Issue 的產出**。  

> **觀察**：若未來出現持續的 Issue 活動，相關主題將會在此區塊聚合。

## Constraints
1. **內容限制**  
   - 不得直接複製 Issue 標題或內容，僅能抽象化為規則、決策或限制。  
   - 必須保留工程可讀性，避免冗長敘述。  

2. **資料來源**  
   - 只接受 **GitHub issue / comment** 為原始依據；其他非結構化來源需先轉為 Issue 形式。  

3. **更新頻率**  
   - 每日快照僅在有新 Issue 時產生實質變更，否則保留既有記憶。  

4. **不確定資訊的處理**  
   - 若資訊僅在單一天出現且未形成穩定事實，須放入 **Open Loops**，不列為 Stable Context。
