# Repository Memory

## Stable Context
- **記憶管理流程**  
  - 以 GitHub Issue / Comment 為唯一原始資料來源，所有長期記憶皆應從這些來源抽取。  
  - `shared/manual.md` 為人工維護的長期記憶檔案，僅存放 **穩定規則、長期決策、常見限制與 repo 習慣**，不會被自動流程覆寫。  
  - 每日快照 (`daily/*.json`) 由活躍的 Issue Agents 依照最近 30 天內的 Issue 狀態彙整，產出跨 Issue 主題、決策與未完成事項的摘要。  

- **Agent 行為原則**  
  - 若當日快照找不到可用 Issue，則保留既有記憶，不新增或刪除內容。  
  - 任何跨 Issue 主題或決策的變更，必須在 Issue 中明確標示（例如使用標籤或特定關鍵字），才能被 agents 辨識。  

- **記憶更新節點**  
  - **每日快照**：自動在每日結束時產生，提供最新的跨 Issue 主題與 Open Loops。  
  - **手動筆記**：由人類維護者定期審核與更新，確保長期規則與限制不會因短期噪音而遺失。  

## Recent Themes
> 目前的每日快照（2026‑09‑24 至 2026‑10‑01）皆未偵測到可用 Issue，故無可辨識的跨 Issue 主題或重複出現的議題。  
- **暫無重複主題**：所有天數的快照皆顯示「目前沒有可辨識的跨 issue 主題」。  

## Constraints
- **資料來源限制**  
  - 只能引用 GitHub Issue / Comment 作為原始事實來源；`shared/manual.md` 只能作為摘要與規則的存放地。  
  - 不得直接複製 Issue 原文於本記憶檔，必須以概念化、抽象化的方式呈現。  

- **記憶穩定性**  
  - 若某資訊僅在單一天出現且未形成持續模式，必須歸類於 **Open Loops** 或 **Recent Themes**，不可寫成穩定規則。  

- **更新頻率**  
  - 每日快照若持
