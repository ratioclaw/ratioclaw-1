# Repository Memory

## Stable Context
- **資料來源**：所有長期記憶皆以 GitHub Issue 與 Comment 為原始事實來源，除非另有手動標註，否則不直接引用原文。  
- **手動筆記**：`shared/manual.md` 為唯一由人類維護的長期記憶檔案，裡面應僅保留 **穩定規則、長期決策、常見限制** 以及 **repo 內部慣例**。此檔案會被 `compact-memory` 工作流讀取，但不會被自動覆寫。  
- **記憶蒸餾流程**：每日快照 (daily snapshots) 只在有可用 Issue 時才會產生跨 Issue 主題、決策與開放迴路；若無可用 Issue，則保留既有記憶，不新增內容。  
- **一致性原則**：若不同來源的資訊相互矛盾，必須在本文件中標註「不確定」或「需進一步驗證」；不允許自行推測未被確認的事實。  

## Recent Themes
> 近期（過去 30 天）每日快照皆顯示 **無可用 Issue**，因此未出現可辨識的跨 Issue 主題、決策或新興趨勢。  
- **缺乏活躍 Issue**：連續 6 天（2026‑09‑12 至 2026‑09‑18）皆未偵測到任何可處理的 Issue。  
- **待更新**：所有快照的「Open Loops」皆指向「等待下一輪 Issue 更新後再整理」，顯示目前的記憶狀態主要是 **待命**。  

## Constraints
1. **不複製原始 Issue 文字**：任何自動生成的長期記憶必須以摘要或抽象形式呈現，避免直接貼上 Issue 內容。  
2. **手動筆記優先**：`shared/manual.md` 中的條目視為最高可信度，除非有明確的更新證據。  
3. **資訊新鮮度**：只有在 Issue 活躍且跨日持續出現的資訊，才可升級為「Stable Context」或「Recent Themes」。  
4. **工程可讀性**：所有條目須保持簡潔、結構化，方便程式或其他 agents 解析。  
5. **不確定性標示**：若資訊來源不足或相互衝突，必須在相應節點加註 `⚠️ 不確定`。
