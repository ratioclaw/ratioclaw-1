# Repository Memory  

## Stable Context  
- **資料來源原則**：所有可追溯的事實與決策必須以 GitHub Issue 或 Comment 為唯一原始來源。  
- **手動筆記角色**：`shared/manual.md` 只保存 **長期穩定規則、決策、限制與 repo 習慣**，不會被自動流程覆寫，也不應直接複製 Issue 原文。  
- **compact‑memory 工作流程**：會在每次執行時讀取 `shared/manual.md`，但不會改寫它；因此手動筆記是 **唯一的長期記憶入口**。  
- **repo 習慣**：  
  1. 以 Issue 為單位追蹤工作項目與待辦。  
  2. 每日快照只聚焦於過去 30 天內的 Issue，且上限 100 件。  
  3. 若快照期間無可用 Issue，則保留既有記憶，不產生新條目。  

> **不確定性**：目前未在快照中觀測到任何具體 Issue、決策或跨 Issue 主題，故無法補充其他長期規則或流程。

## Recent Themes  
- **缺乏活躍 Issue**：連續 7 天（2026‑09‑21 至 2026‑09‑27）每日快照皆報告「本次整理視窗沒有可用 issue」，顯示近期 repo 內缺乏待處理或新建立的 Issue。  
- **無跨 Issue 主題**：每日快照均未偵測到可辨識的跨 Issue 主題或共通議題。  
- **無新決策**：同樣因缺乏 Issue，未產生任何跨 Issue 決策。  

## Constraints  
1. **不允許直接複製 Issue 原文**：手動筆記必須以摘要或規則形式呈現，避免冗長與重複。  
2. **記憶更新依賴 Issue 活動**：若 Issue 數量為零，系統僅保留現有記憶，不會自行創建新條目。  
3. **每日快照範圍限制**：只檢視過去 30 天內、最多 100 件 Issue，超出範圍的資訊不會自動納入記憶。
