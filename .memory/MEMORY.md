# Repository Memory

## Stable Context
- **長期規則與決策**  
  - 只將 **GitHub Issue / Comment** 視為原始事實來源，任何摘要或記錄皆須以此為根基。  
  - `shared/manual.md` 為 **人工維護的長期記憶**，其中列出的「穩定規則、長期決策、常見限制、repo 習慣」皆視為不變的基礎資訊。  
  - **不允許** 直接複製完整 Issue 內容於本檔；只能抽象化、概念化後寫入。  
  - `compact‑memory` 工作流程會 **讀取** 本手動筆記，但 **不會覆寫**，因此本檔的內容必須保持可讀且不與原始 Issue 重複。

- **repo 習慣**（從手動筆記推測）  
  1. 所有新資訊皆由 **issue agents** 每日快照彙整。  
  2. 快照只在 **過去 30 天** 內的 Issue 中搜尋，超過此範圍的議題不會自動納入。  
  3. 若當日快照找不到可用 Issue，則 **保留既有記憶**，不新增或刪除任何條目。  

- **資訊蒸餾原則**  
  - 重複出現的事務會被提升為「穩定規則」或「長期主題」。  
  - 僅在單日出現且未形成趨勢的資訊，放入 **近期主題** 或 **Open Loops**，不寫成固定規則。  

## Recent Themes
> 目前 **2026‑08‑13 至 2026‑08‑19** 的每日快照皆顯示「本次整理視窗沒有可用 issue」，因此 **未偵測到任何跨 Issue 主題**、決策或新興趨勢。  
- **無新主題**：每日皆回報「無可用 Issue」 → 表示近期 repo 內缺乏活躍議題或 issue 被歸檔/關閉。  

## Constraints
1. **資訊來源限制**  
   - 必須以 **GitHub Issue / Comment** 為唯一事實來源；任何推論皆需標示為「根據現有 Issue」或「推測」。
2. **內容重複禁忌**  
   - 本檔不得直接複製 Issue 原文，也不應重複手動筆記的文字敘述（除非作為規則引用）。  
3. **時間範圍**  
   - 只考慮過去 **30 天** 內的 Issue；超出此範圍的資訊
