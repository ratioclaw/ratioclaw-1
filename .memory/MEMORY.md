# Repository Memory

## Stable Context
- **長期規則**  
  - 只以 GitHub Issue / Comment 為原始資料來源，任何摘要或記錄皆須基於這些正式條目。  
  - 手動維護的 `shared/manual.md` 為唯一的長期記憶檔案，**不會**被自動流程覆寫。  
  - 任何跨 Issue 的決策或主題，若未在 Issue 中明確形成，皆不列入穩定規則。  

- **Repo 習慣**  
  - 每日快照 (`daily/*.json`) 由各 Issue Agent 產出，若當天無可用 Issue，快照僅保留既有記憶。  
  - `compact‑memory` 工作流會讀取 `shared/manual.md` 以取得長期上下文，並以此指導後續摘要。  
  - 所有摘要必須 **避免逐段複製原文**，而是以精煉、可重用的方式呈現。  

- **長期決策**  
  - 目前尚未有跨 Issue 的正式決策被記錄，故無可列入的長期決策。  

## Recent Themes
> 近期（過去 30 天）未偵測到任何可辨識的跨 Issue 主題或重複出現的議題。每日快照皆顯示「本次整理視窗沒有可用 issue」，因此目前沒有可供蒸餾的近期主題。

## Constraints
1. **資料來源限制**  
   - 只能引用 GitHub Issue / Comment，其他非結構化來源（如聊天記錄、即時訊息）不列入正式記憶。  
2. **內容呈現限制**  
   - 不得直接複製 Issue 原文，必須以摘要、概念化的方式重構。  
   - `shared/manual.md` 為唯一手動編輯的長期記憶檔，任何自動化流程不得改寫此檔。  
3. **更新頻率**  
   - 若當天無可用 Issue，快照僅保留先前記憶，**不會**自行產生新資訊。  

## Open Loops
- **待處理 Issue**：目前所有每日快照皆顯示「等待下一輪 issue 更新後再整理」，表示尚未有新 Issue 產生或被標記為可用。  
- **未確定的長期規則**：若未來出現持續出現的主題或決策，需要在 `shared/manual.md` 中手動加入，否則仍屬於不確定狀態。  

> **龍蝦小提醒**：我們的記憶庫目前是靜止的，只有當新的 Issue 流入時，我們才能為主人捕捉新的生活與工作
