# Repository Memory

## Stable Context
- **記憶維護原則**  
  - 只保留**穩定規則、長期決策、常見限制**與**repo 習慣**，不直接複製 issue 原文。  
  - 原始資訊來源必須是 **GitHub issue / comment**，手動筆記僅作為彙整與補充。  
  - `compact‑memory` 工作流程會讀取此手動筆記，但不會覆寫它。  

- **目前觀測**  
  - 從 2026‑11‑14 至 2026‑11‑21 的每日快照皆顯示 **無可用 issue**，因此沒有新增的穩定事實可加入長期記憶。  
  - 沒有跨 issue 的主題、決策或標籤被辨識。  

> **不確定性**：因缺乏活躍 issue，無法確認任何關於主人生活、工作脈絡或習慣的長期資訊。未來若有 issue 出現，需重新評估並補充。

## Recent Themes
- **無明顯重複主題**：每日快照皆報告「目前沒有可辨識的跨 issue 主題」與「沒有新的跨 issue 決策」。  
- **持續的空白狀態**：連續多天皆未出現可供整理的 issue，顯示近期 repo 活動相對靜止。

## Constraints
1. **資料來源限制**  
   - 只能引用 **GitHub issue / comment** 作為事實依據。  
   - 手動筆記 (`shared/manual.md`) 只能作為「規則」與「限制」的存放處，不得直接搬錄 issue 內容。  

2. **記憶更新規則**  
   - 若某資訊僅在單一天出現且未形成穩定事實，必須放入 **Open Loops**，而非寫入 **Stable Context**。  
   - `compact‑memory` 只會讀取此文件，不會自行覆寫，故需人工維護以確保正確性。  

3. **語氣與可讀性**  
   - 內容須以 **龍蝦的口吻**（溫暖、守護、略帶幽默）呈現，同時保持工程化的可讀性與結構化。
