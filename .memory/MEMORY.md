# Repository Memory

## Stable Context
- **長期規則**  
  - 只將 **GitHub Issue / Comment** 視為原始事實來源，任何摘要或結論皆須基於這些資料。  
  - **Shared Manual Notes**（`shared/manual.md`）是人工維護的長期記憶，**不可被自動流程覆寫**，亦不應直接複製完整 Issue 內容。  
  - 代理（agents）在整理日誌時，必須 **蒸餾**（distill）資訊為可重用的上下文，避免逐段搬錄原文。  
  - 若資訊出現矛盾或不足，必須在記錄中明確標示 **不確定性**，而非強行斷言。

- **Repo 習慣**  
  - 每日快照（daily snapshots）會在過去 30 天內檢索最多 100 個 Issue，並以 **deterministic** 方法產出跨 Issue 主題與決策。  
  - 快照結果若無可用 Issue，則保留既有記憶，不新增或刪除任何條目。  
  - 產出文件（如本 `MEMORY.md`）僅作為 **長期記憶的 curated 版本**，不充當索引或原始日誌。

## Recent Themes
- **無可辨識跨 Issue 主題**  
  - 從 2026‑08‑19 至 2026‑08‑25 的每日快照皆顯示「目前沒有可辨識的跨 issue 主題」。  
  - 這表示近期（過去一週）在 repo 中未產生新的、可被多個 Issue 共同關聯的議題或決策。

- **持續缺乏可用 Issue**  
  - 每日快照皆報告「本次整理視窗沒有可用 issue」，暗示在過去 30 天內，**Issue 活動極少或全部已關閉**。  
  - 這是一個值得關注的趨勢，可能代表開發節奏放緩、需求暫停，或是 Issue 標籤/篩選設定有誤。

## Constraints
1. **資料來源限制**  
   - 只能引用 Issue / Comment 作為事實依據；若缺乏此類來源，則不得自行創造事實。  
2. **手動筆記保護**  
   - `shared/manual.md` 必須保持原樣，任何自動化流程不得寫入或覆寫此檔。  
3. **資訊蒸餾原則**  
   - 必須將重複出現的資訊抽象為 **可重用的規則或上下文**，而非逐段複製原始文字。
