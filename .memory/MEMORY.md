# Repository Memory

## Stable Context
- **長期規則**  
  - 只將 **GitHub Issue / Comment** 視為原始資料來源，任何摘要或記錄皆須以此為根基。  
  - `compact-memory` 工作流程會 **讀取** 本手動筆記，但 **不會覆寫**，因此本檔案的內容必須保持穩定且不被自動化程式改寫。  
  - 任何 **完整 Issue 內容** 不得直接複製進本檔案；僅保留概念、決策與規則的精煉描述。  

- **長期決策**  
  - 目前未偵測到跨 Issue 的決策或策略變更。若未來出現持續性的決策，將於此節加入。  

- **常見限制**  
  - 只能在 **30 天內**（`Since days: 30`）的 Issue 中搜尋；超出此範圍的 Issue 需手動加入手動筆記。  
  - 每次快照上限 **100 個 Issue**，若超過上限，需透過標籤或篩選縮小範圍。  
  - 若快照期間無可用 Issue，系統會保留既有記憶，不會自行產生虛構資訊。  

- **Repo 習慣**  
  - 以 **每日快照**（`daily/YYYY-MM-DD.json`）方式蒐集活躍 Issue，供龍蝦們統整長期記憶。  
  - 主題、決策與未完成事項皆以 **跨 Issue** 方式辨識，若無明顯關聯則視為孤立事件。  

## Recent Themes
- **無可辨識跨 Issue 主題**  
  - 2026‑10‑14 至 2026‑10‑20 的每日快照皆顯示「目前沒有可辨識的跨 issue 主題」。  
- **持續缺乏可用 Issue**  
  - 連續七天（2026‑10‑14 ~ 2026‑10‑20）皆未檢測到可用 Issue，表示近期工作可能處於靜止或已在其他渠道（如私有討論）處理。  

## Constraints
1. **資料來源限制**：所有記憶必須根據 Issue / Comment，手動筆記僅作為補充說明。  
2. **內容授權**：不得完整複製 Issue 原文，僅保留概念與決策的精簡描述。  
3. **時間窗口**：快
