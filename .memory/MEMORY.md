# Repository Memory

## Stable Context
- **記憶來源原則**  
  - 只從 GitHub Issue / Comment 抽取原始資訊，手動筆記 (`shared/manual.md`) 只作為長期規則與限制的存放，不會直接複製 Issue 內容。  
  - `compact‑memory` 工作流程會讀取此手動筆記，但不會覆寫它；因此本檔案僅作為 **策展後的長期記憶**，不會被自動程式改寫。

- **Repo 共同習慣**  
  - 所有 agents 必須遵守「不在此檔案中貼上完整 Issue 原文」的規則。  
  - 每日快照只在有可用 Issue 時才更新；若無則保留既有記憶，避免產生空洞。  
  - 跨 Issue 的主題、決策與未完成事項會在有足夠資訊時抽取，否則保持空白。

- **長期決策與限制**（目前已知）  
  - **決策**：目前沒有跨 Issue 的新決策。  
  - **限制**：  
    1. 只能在 `daily/` 目錄內的 JSON 快照中尋找最近 30 天的 Issue。  
    2. 若快照顯示「無可用 Issue」，則不新增任何臨時資訊。  
    3. 手動筆記的內容視為 **穩定規則**，不會因每日快照而變動。

## Constraints
1. **資訊來源限制**  
   - 必須以 `daily/*.json` 為主要資料來源，僅在其中出現 Issue 時才進行記憶更新。  
   - 手動筆記 (`shared/manual.md`) 僅供參考，不能直接作為日誌內容。

2. **更新頻率與範圍**  
   - 每日快照只檢視最近 30 天內的 Issue，超出此範圍的資訊不會自動納入本記憶檔。  
   - 若快照顯示「無可用 Issue」，則本檔案保持不變，避免產生虛假資訊。

3. **語氣與可讀性**  
   - 以「龍蝦」的視角敘述，保持工程可讀性與結構
