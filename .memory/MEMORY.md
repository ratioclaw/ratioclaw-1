# Repository Memory

## Stable Context
- **手動筆記為長期記憶的唯一來源**：`shared/manual.md` 內的內容被視為穩定規則、長期決策與共通限制，所有 agent 必須遵守此檔案的指示。  
- **不可直接複製 Issue 原文**：原始資料只能來自 GitHub Issue / Comment，`manual.md` 僅作為摘要與指引，**不會被覆寫**。  
- **compact‑memory 工作流程**：在產生或更新長期記憶時，系統會先讀取 `manual.md`，再根據每日快照蒸餾資訊；若快照中無新資訊，則保留既有記憶。  
- **Issue 數量與時間範圍限制**：每日快照只檢視最近 30 天、最多 100 個 Issue，超出範圍的資訊不會自動納入長期記憶。  
- **跨 Issue 主題與決策的辨識**：只有在快照能夠辨識出跨 Issue 的共同主題或決策時，才會被加入 `Stable Context`；目前尚未出現此類資訊。  

> **不確定性**：目前沒有任何具體的穩定規則（例如程式碼風格、部署流程）被手動記錄於 `manual.md`，因此只能以上述通用原則作為長期記憶的基礎。

## Recent Themes
- **缺乏活躍 Issue**：自 2026‑09‑15 起的七天快照（至 2026‑09‑21）皆顯示「本次整理視窗沒有可用 issue」，代表近期 repository 內沒有新開或待處理的 Issue。  
- **無跨 Issue 主題**：每日快照均回報「目前沒有可辨識的跨 issue 主題」，說明近期沒有重複出現的議題或需求。  
- **無新決策**：同樣因缺乏 Issue，系統未產生任何跨 Issue 決策。  

> **不確定性**：若在未來的快照中出現 Issue，需重新評估是否形成新的主題或決策。

## Constraints
1. **資料來源限制**  
   - 只能從 GitHub Issue / Comment 取得原始資訊。  
   - `manual.md` 只能作為摘要與指引，**不允許直接複製完整 Issue 內容**。  

2. **記憶更新規則**  
   - 每日快照
