# Repository Memory

## Stable Context
- **長期規則與決策**  
  - 以 GitHub Issue 與 Comment 為唯一原始資料來源，所有記憶的抽取與整理必須根據這些條目。  
  - `shared/manual.md` 為人工維護的長期記憶檔案，僅用於保存**穩定規則、長期決策、常見限制**與**repo 習慣**，不會被自動流程覆寫。  
  - 任何自動化的 memory 工作流（如 compact‑memory）只能**讀取**此手動筆記，**不得**直接寫入或覆蓋。

- **Repo 習慣**  
  - Issue 標籤、狀態與內容的變化是記憶更新的觸發點。  
  - 每日快照只會在「有可用 Issue」時產生跨 Issue 主題、決策與開放迴路的摘要；若無 Issue，則保留既有記憶不變。  

- **資訊安全與可讀性**  
  - 不得完整複製 Issue 原文於長期記憶檔案，僅保留必要的抽象資訊與結論。  
  - 記憶內容須保持工程可讀性，方便後續 agent 與人類快速定位相關脈絡。

## Constraints
1. **資料來源限制**  
   - 只能從 GitHub Issue / Comment 取得資訊；其他來源（如聊天記錄、外部文件）不列入正式記憶。  
2. **手動筆記不可覆寫**  
   - `shared/manual.md` 只接受人工編輯，任何自動化流程必須避免寫入此檔。  
3. **避免冗餘**  
   - 長期記憶不應重複列出每日快照的原始文字，僅保留抽象化的結論或規則。  
4. **不確定資訊標示**  
   - 若某資訊僅在單一天出現且未形成穩定事實，必須放入「Open Loops」或以「不確定」標記，避免寫成永久規則。
