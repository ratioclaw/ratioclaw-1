# Repository Memory

## Stable Context
- **長期規則**  
  - 只以 GitHub Issue / Comment 為原始資料來源，任何摘要或記錄皆須基於這些正式條目。  
  - 手動維護的 `shared/manual.md` 為唯一的長期記憶入口，**不會**被自動流程覆寫。  
  - 任何跨 Issue 的決策或主題必須在 Issue 本身或其討論串中明確表述，否則不列入長期記憶。  

- **Repo 習慣**  
  - 每日快照 (`daily/*.json`) 只在有可用 Issue 時才產出具體內容，否則保留既有記憶。  
  - `compact‑memory` 工作流會讀取 `shared/manual.md` 以取得穩定上下文，並以此為基礎蒸餾每日快照。  
  - 所有長期記憶必須保持 **可機器讀取**、**易於搜尋**，避免冗長的原文複製。  

- **決策紀錄**  
  - 目前尚未出現跨 Issue 的決策，故無固定決策規則可記錄。  

## Recent Themes
> 近期（過去 30 天）未偵測到任何可辨識的跨 Issue 主題或重複出現的議題。  
> - 每日快照皆顯示「本次整理視窗沒有可用 issue」，表示目前的工作板上缺乏活躍項目。  

## Constraints
1. **資料來源限制**  
   - 只能引用 Issue / Comment，禁止直接搬錄原始 Issue 文字。  
2. **更新頻率**  
   - 若 30 天內無新 Issue，快照仍會產生，但內容僅保留「無可用 Issue」的說明。  
3. **資訊完整性**  
   - 若資訊不足或相互矛盾，必須在本文件中明確標示「不確定」或「缺乏資料」。  
4. **語言與格式**  
   - 所有長期記憶必須以繁體中文撰寫，使用 Markdown 結構，保持工程可讀性。  

## Open Loops
- **待處理 Issue**：目前沒有任何待處理的 Issue，所有每日快照皆顯示「等待下一輪 issue 更新後再整理」。  
- **未來主題探索**：若未來出現新的 Issue，需觀察是否形成跨 Issue 主題或決策，並將其納入 `Stable Context` 或 `Recent Themes`。  
- **資訊缺口**：缺乏任何具體的長期決策、限制或工作流程細節，需在未來的 Issue 中主動記錄此類資訊，以豐富本記
