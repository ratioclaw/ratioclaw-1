# Repository Memory

## Stable Context
- **資料來源**：所有長期記憶皆以 GitHub Issue / Comment 為原始依據，手動維護的 `shared/manual.md` 只作為摘要與規則的存放，不會被自動覆寫。  
- **記憶更新流程**：每日快照會由活躍的 Issue Agents 彙整，若當日無可用 Issue，則保留既有記憶不變。  
- **repo 習慣**：  
  - 以 deterministic 的摘要方式產出每日快照。  
  - 每次快照限制 100 筆 Issue，回溯 30 天內的變動。  
  - 只在跨 Issue 有可辨識的主題、決策或未完成事項時才更新相應章節。  

> **不確定性**：目前尚未觀測到任何穩定規則、長期決策或常見限制，以上內容僅為流程層面的共識。

## Recent Themes
- **無可辨識跨 Issue 主題**：過去 10 天（2026‑10‑07 至 2026‑10‑15）的所有快照皆顯示「目前沒有可辨識的跨 issue 主題」。  
- **持續無 Issue**：每日皆報告「本次整理視窗沒有可用 issue」，說明近期 repository 內缺乏待處理或新建立的 Issue。  

> **不確定性**：若未來出現新 Issue，可能會產生新的主題與決策，需重新評估此區塊。

## Constraints
1. **手動筆記不可被自動覆寫**：`shared/manual.md` 只作為長期記憶的補充說明，系統不會直接寫入或修改其內容。  
2. **Issue 為唯一真實來源**：所有可供抽取的事實必須能在 GitHub Issue / Comment 中追溯。  
3. **摘要限制**：每日快照僅考慮最近 30 天、最多 100 筆 Issue，超出範圍的資訊不會自動納入本記憶庫。  

> **不確定性**：若未來引入其他資料來源（如 PR、Wiki），需重新定義限制條件。

## Open Loops
- **等待新 Issue**：目前所有快照皆顯示「等待下一輪 issue 更新後再整理」，代表缺乏可供分析的資料。  
- **潛在主題探索**：若未來出現跨 Issue 的共通關鍵字或標籤，需即時建立相應的「Cross‑Issue Themes」與「Decisions」條目。  
- **未完成事項**：目前無具體的
