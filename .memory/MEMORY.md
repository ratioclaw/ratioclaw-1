# Repository Memory

## Stable Context
- **長期記憶維護原則**  
  - 只保留 **穩定規則、長期決策、常見限制** 以及 **agent 共同遵守的 repo 習慣**。  
  - 原始的 GitHub issue / comment 仍是事實來源，**不直接複製** 原文於此檔案。  
  - `compact‑memory` 工作流程會讀取本手動筆記，但 **不會覆寫**，因此本檔案必須保持 **只讀**、**不可自動更新** 的性質。  

- **目前已確認的穩定規則**（來自手動筆記的指示）  
  1. **資訊分類**：所有長期資訊必須放在此 `MEMORY.md`，每日快照僅作為暫存與蒸餾來源。  
  2. **避免冗餘**：不重複 issue 標題或每日原始敘述，僅抽取可重用的概念與規則。  
  3. **不確定資訊**：若每日快照只出現一次且未形成持續模式，應歸入 **Open Loops**，不列為穩定規則。  

- **已知的長期決策**  
  - 目前尚未在任何 issue 中形成跨 issue 的決策，故無可記錄的長期決策。  

- **常見限制**  
  - **資料來源限制**：只能從過去 30 天內的 issue 取得資訊；若超出此範圍或無可用 issue，則保持現有記憶不變。  
  - **標籤限制**：每日快照未顯示任何 Top Labels，表示目前沒有特別標記的議題類別。  

## Recent Themes
- **缺乏可用 Issue**：自 2026‑08‑03 起的每日快照皆顯示「本次整理視窗沒有可用 issue」，說明近期（過去兩週）專案內缺乏活躍的議題或所有議題已被關閉。  
- **無跨 Issue 主題**：每日快照均未偵測到跨 issue 的共同主題，表示目前沒有正在進行的多議題協作或共通問題。  

> **註**：上述主題僅基於最近 10 天的快照，若未來出現新議題，相關主題將會在此區塊更新。
